# Практическая работа 2, вариант 27

Инструмент построения графа зависимостей npm на Python 3.9 или новее.
Этап 4 дополнительно выводит обратные зависимости пакета: все пакеты,
которые зависят от него напрямую или через другие пакеты. Для обхода
обратных связей используется рекурсивный BFS предыдущего этапа.
Обычный режим строит транзитивный граф зависимостей пакета.
Повторные посещения пакетов исключены, поэтому циклы не останавливают
обход. Данные можно получить из npm-реестра или из тестового JSON-файла.
Для HTTP-запроса и разбора JSON используются модули стандартной библиотеки
Python. PyYAML нужен только для чтения конфигурации.

`load_config()` читает настройки, `direct_dependencies()` получает прямые
зависимости версии `latest`, `build_graph()` обходит их по уровням,
`load_test_repository()` читает тестовый файл, `reverse_graph()` меняет
направление связей, а `main()` выводит результат.
При ошибке приложение пишет в stderr без traceback.

## Установка, запуск и тесты

Сборка отдельного файла не нужна. Установи библиотеку для чтения YAML:

```sh
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
./run.sh --config config.yaml
make check
```

`--config` задаёт путь к YAML-файлу. Без этой опции `run.sh` использует
`config.yaml` из корня проекта. Скрипт можно вызвать из другой папки.
Все пять рабочих настроек берутся только из YAML; командная строка
выбирает сам файл конфигурации. Также доступны `make run` и `make test`.

## Настройки

| Ключ | Значение |
| --- | --- |
| `package_name` | Имя npm-пакета; в тестовом режиме — заглавные латинские буквы. |
| `repository` | URL npm-реестра или путь к JSON-файлу относительно YAML. |
| `test_mode` | YAML-значение `true` или `false`: читать тестовый файл или обращаться к npm-реестру. |
| `output_file` | Имя PNG-файла для этапа 5; сейчас файл не создаётся. |
| `ascii_tree` | YAML-значение `true` или `false`: включить ASCII-дерево зависимостей на этапе 5. |
| `reverse_mode` | Необязательное YAML-значение `true` или `false`. При `true` выводит обратные зависимости. |
| `graph_root` | Корень npm-графа; нужен для обратного обхода с реестром. |

Пример конфигурации находится в `config.yaml`:

```yaml
package_name: express
repository: https://registry.npmjs.org
test_mode: false
output_file: graph.png
ascii_tree: false
```

Пример запуска с тестовым репозиторием:

```text
$ ./run.sh --config examples/test-config.yaml
Граф зависимостей A:
A -> B, C
B -> D
C -> D
D -> A
```

Здесь `A → B → D → A` образует цикл, а `D` достижим через `B` и `C`.
Пустой граф демонстрирует команда
`./run.sh --config examples/test-empty.yaml`: она выводит `E -> (нет)`.
Тестовый репозиторий описан в `examples/test-repository.json`: объект
содержит имена пакетов из заглавных латинских букв и списки зависимостей.
Реальный реестр проверяется командой `./run.sh` с обычным `config.yaml`.
Для каждого пакета запрашивается манифест `latest`; диапазоны версий
зависимостей пока не разрешаются.

Обратный обход проверяется на двух случаях:

```text
$ ./run.sh --config examples/reverse-d.yaml
Обратные зависимости D:
B
C
A

$ ./run.sh --config examples/reverse-e.yaml
Обратные зависимости E:
(нет)
```

Пакеты `B` и `C` зависят от `D` напрямую, а `A` — через них. Сам `D`
не повторяется в выводе при замыкании цикла.

Для демонстрации на npm используется граф зависимостей `is-even`.
Программа сама получает манифесты пакетов из реестра, затем ищет пакеты,
которые зависят от `is-number` внутри этого графа:

```text
$ ./run.sh --config examples/reverse-npm.yaml
Обратные зависимости is-number:
is-odd
is-even
```

Для сравнения в отдельном временном проекте можно выполнить
`npm install is-even --ignore-scripts`, затем `npm ls is-number --all`.
npm также показывает цепочку `is-even -> is-odd -> is-number`, но с
конкретными установленными версиями. Программа запрашивает `latest`
для каждой вершины и выводит только имена: она не разрешает диапазоны
версий, поэтому для других пакетов связи могут отличаться от `npm ls`.
Поскольку npm-реестр не отдаёт полный список пакетов, зависящих от
произвольного пакета, `graph_root` ограничивает область анализа.

## Ошибки конфигурации

Приложение сообщает об ошибке в stderr и завершает работу с кодом `2`.
Проверки покрывают каждый параметр и сам YAML-файл:

| Параметр | Пример ошибки |
| --- | --- |
| `package_name` | `bad package` или `a` в тестовом режиме |
| `repository` | `not-a-url` в обычном режиме или отсутствующий файл в тестовом |
| `test_mode` | `maybe` вместо логического значения |
| `output_file` | `graph.svg` вместо имени PNG-файла |
| `ascii_tree` | `1` вместо логического значения |
| `graph_root` | Отсутствует в обратном npm-режиме или содержит неверное имя |
| YAML-файл | Нет файла, неверный синтаксис или отсутствует обязательный ключ |

Например, после замены `output_file: graph.png` на
`output_file: graph.svg` в копии конфигурации:

```text
$ ./run.sh --config bad-config.yaml
Ошибка: output_file: ожидается имя PNG-файла
```

Все перечисленные случаи проверяются автоматическими тестами в `tests/`.
Тесты проверяют настройки, прямые и обратные зависимости, порядок BFS,
циклы и чтение тестового файла. HTTP-ответ подменяется готовым JSON.
Код находится в `main.py` и `src/dependency_graph/`.
