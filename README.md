# Практическая работа 2, вариант 27

Инструмент строит транзитивный граф зависимостей npm-пакета. Он читает
настройки из YAML, получает манифесты напрямую из npm-реестра через HTTP,
обходит граф рекурсивным BFS, печатает описание на языке D2 и сохраняет PNG.
По желанию печатает ASCII-дерево. Для проверки циклов поддерживается
тестовый JSON-репозиторий.

Для получения зависимостей используются только модули стандартной библиотеки
Python. PyYAML читает конфигурацию, а программа `d2` строит изображение из
готового описания графа. Установка npm для работы приложения не нужна.

`load_config()` проверяет настройки, `direct_dependencies()` получает
прямые зависимости версии `latest`, `build_graph()` обходит их по уровням,
`load_test_repository()` читает тестовый файл. `to_d2()` описывает все связи,
`render_png()` вызывает D2, `ascii_tree()` строит текстовое дерево.
При ошибке приложение пишет в stderr и возвращает код `2`.

## Установка и запуск

Нужны Python 3.9 или новее и [D2 CLI](https://d2lang.com/tour/install/).
На macOS его можно установить командой `brew install d2`.

```sh
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
./run.sh --config examples/npm-is-odd.yaml
make check
```

Без `--config` используется `config.yaml` с пакетом `express`.
Скрипт `run.sh` можно вызвать из другой папки: он переходит в корень
проекта. `make run` запускает приложение, `make test` и `make check`
запускают тесты. Имя PNG берётся из настройки `output_file`; файл
сохраняется в текущем каталоге приложения и исключён из Git.

## Настройки

| Ключ | Значение |
| --- | --- |
| `package_name` | Имя npm-пакета; в тестовом режиме — заглавные латинские буквы. |
| `repository` | HTTP(S) URL npm-реестра или путь к тестовому JSON. Путь считается от YAML-файла. |
| `test_mode` | `true` для тестового файла, `false` для реестра. |
| `output_file` | Имя файла PNG без каталога, например `graph.png`. |
| `ascii_tree` | `true` для печати ASCII-дерева, `false` для вывода только D2. |

Параметры `test_mode` и `ascii_tree` принимают только
логические значения YAML. Недопустимые имена, URL, пути и расширение
выходного файла сообщаются как ошибки конфигурации.

## Примеры визуализации

Три конфигурации для реального npm-реестра:

```sh
./run.sh --config examples/npm-is-number.yaml
./run.sh --config examples/npm-is-odd.yaml
./run.sh --config examples/npm-is-even.yaml
```

| Пакет | Связи в D2 | Созданный файл |
| --- | --- | --- |
| `is-number` | Только вершина `"is-number"` | `is-number.png` |
| `is-odd` | `"is-odd" -> "is-number"` | `is-odd.png` |
| `is-even` | `"is-even" -> "is-odd"`, `"is-odd" -> "is-number"` | `is-even.png` |

Например, запуск `is-even` печатает D2 и дерево:

```text
D2-граф зависимостей is-even:
"is-even" -> "is-odd"
"is-odd" -> "is-number"
"is-number"
PNG: is-even.png
ASCII-дерево:
is-even
`-- is-odd
    `-- is-number
```

Тестовый запуск `./run.sh --config examples/test-config.yaml` показывает
цикл `A -> B -> D -> A` и общую зависимость `D` у `B` и `C`.
Повторные вершины в ASCII-дереве помечаются словом `(повтор)`, а D2
содержит все рёбра. Пакет `E` без зависимостей проверяется командой
`./run.sh --config examples/test-empty.yaml`. JSON-граф находится в
`examples/test-repository.json`.

## Сравнение с npm

Для сравнения каждый из трёх пакетов был установлен отдельно во временный
проект через `npm install`, затем выполнена команда `npm ls --all`.
Имена пакетов совпали для `is-number` и `is-odd`. Для `is-even` npm
показал дополнительную цепочку `kind-of -> is-buffer`:

```text
is-number@7.0.0
is-odd@3.0.1 -> is-number@6.0.0
is-even@1.0.0 -> is-odd@0.1.2 -> is-number@3.0.0
             -> kind-of@3.2.2 -> is-buffer@1.1.6
```

Причина расхождения: приложение запрашивает `latest` для каждой найденной
вершины и выводит имена без версий. npm разрешает диапазоны версий из
манифеста и показывает реально установленные версии. У `is-even@1.0.0`
запрошен старый `is-odd`, поэтому его транзитивные зависимости отличаются
от зависимостей актуального `is-odd@3.0.1`. npm также показывает корень
временного проекта; на D2-диаграмме корнем служит анализируемый пакет.
Подробнее о выводе npm: [npm ls](https://docs.npmjs.com/cli/commands/npm-ls/).

## Проверка ошибок

Тесты в `tests/` проверяют каждый параметр YAML, прямые и обратные
зависимости, порядок BFS, циклы, описание D2, ASCII-дерево и PNG.
Например, если в копии YAML указать `output_file: graph.svg`, приложение
выведет `Ошибка: output_file: ожидается имя PNG-файла`.
При отсутствии `d2` выводится `Ошибка: D2 не найден: установите команду d2`.
